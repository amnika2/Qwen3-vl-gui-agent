# 端到端模型对照与 Harness 消融

本轮固定六组，各执行五个应用的 A/B target 流程，共 60 次。使用已有 Base、扩充 SFT 和 GRPO 权重；每项任务从独立应用实例开始，通过真实鼠标键盘操作并提交、检查记录，最后运行独立业务判据。

## 实验配置

| 组 | Actor / Reviewer | 规划 | 长期记忆 | 显式反思 |
| --- | --- | --- | --- | --- |
| base-full | Base | 开 | 开 | 开 |
| sft-full | SFT | 开 | 开 | 开 |
| grpo-full | GRPO | 开 | 开 | 开 |
| grpo-no-planning | GRPO | 关 | 开 | 开 |
| grpo-no-memory | GRPO | 开 | 关 | 开 |
| grpo-no-reflection | GRPO | 开 | 开 | 关 |

规划、摘要和经验总结统一使用 Base。五个应用是 Akaunting、Ampache、Anchor CMS、EasyAppointments 和 emlog；近期动作窗口固定为 4 条，动作预算 30，任务预算 600 秒，动作生成 384 tokens，审查生成 1024 tokens，seed 42，greedy 解码。上下文更新沿用 512 tokens。任务预算包含操作、上下文更新、审查及可用时间内的经验总结；模型在 worker 内预加载，加载时间另有记录。

关闭规划会移除计划、步骤状态、下一步目标及依赖计划的结束核对，保留周期摘要。关闭记忆会移除内置 memory MCP 服务、检索、模型可见的记忆工具和任务后学习保存。关闭显式反思会移除反思字段和错误、循环事件触发的额外反思更新；原始动作/工具反馈、周期计划和摘要、终局审查继续执行。

## 冻结经验

`configs/e2e-memory-seed.yaml` 保存两条从 LiteCart、OpenCart 训练轨迹整理的程序经验，附原始结果、轨迹、提交和重开截图的来源哈希。经验正文描述控件操作、保存和重开方法。原公开任务仅用于经验检索索引。

准备实验时生成冻结 SQLite。启用记忆的每个任务单独复制该库，结束后写入本任务副本；后续评测任务重新从冻结库开始。关闭记忆组不复制、不读取经验库。

## 执行

```bash
.venv/bin/python scripts/run_e2e_experiment.py prepare \
  --suite configs/e2e-60.yaml --directory runs/e2e60-20261109
```

两个终端各运行一个 worker：

```bash
CUDA_VISIBLE_DEVICES=2 LD_LIBRARY_PATH="$PWD/vendor/runtime/root/usr/lib/x86_64-linux-gnu" OMP_NUM_THREADS=4 \
  .model-venv/bin/python -u scripts/run_e2e_experiment.py run \
  --directory runs/e2e60-20261109 --worker 0 --workers 2 --port 13401
```

```bash
CUDA_VISIBLE_DEVICES=3 LD_LIBRARY_PATH="$PWD/vendor/runtime/root/usr/lib/x86_64-linux-gnu" OMP_NUM_THREADS=4 \
  .model-venv/bin/python -u scripts/run_e2e_experiment.py run \
  --directory runs/e2e60-20261109 --worker 1 --workers 2 --port 13402
```

同一 worker 顺序执行分配给它的实验组，复用已经加载的相同权重。每项结果立即保存到 `cells/`；再次运行同一 worker 会跳过已经保存的结果。首次结果保持不变，诊断重跑单列。

```bash
.venv/bin/python scripts/run_e2e_experiment.py report --directory runs/e2e60-20261109
```

输出包括：

- `protocol.json`：六组实际配置、60 格任务、权重标识、任务哈希和冻结经验来源。
- `source.tar.gz`：运行源码与配置快照。
- `worker-0.json`、`worker-1.json`：当前任务及原始运行目录。
- `cells/*.json`：逐任务原始结果索引。
- `results.csv`：终判、执行完成、动作、调用、tokens、耗时和开关。
- `paired-differences.csv`：相同任务的模型与消融配对差异。
- `summary.json`、`summary.md`：模型对照、Harness 消融及配对增减。

## 计分

端到端成功要求 Agent 与独立判据均符合任务预期：A 版 target 应检出缺陷并输出 fail，B 版应输出 pass。独立判据为 pass/fail 表示业务验证已完成；inconclusive、blocked、环境错误和未启动保留在计划分母。

输入/输出 tokens、生成耗时与调用数累计所有模型角色，每次任务清零。统计每组成功数、操作完成数、平均动作/调用/耗时以及同任务的改善、退步和持平。当前 GRPO 权重来自截图审查训练，端到端对照检验该权重进入实际操作闭环后的表现。
