# 开发实验：动作进度记录

预先观察：emlog 的两个 target 试点均因未全选就输入，最终提交 `Original Pen NameSav`；随后重复点击 Save，30 步耗尽。原轨迹：`runs/20261106T163802Z-a2b71478`（A）、`runs/20261106T163802Z-39bde497`（B）。均为 oracle inconclusive。

假设：把“输入前是否全选、最后输入的文本、重复点击次数、最近一次刷新”从短历史中显式保留下来，可以帮助模型修正追加输入并进入重开验证阶段。

唯一方法开关是 `--method qwen-improved`。基线 `qwen-base` 不接收 ledger。两者使用相同模型、截图、用例、8 条动作历史、30 次动作预算和 600 秒执行预算。ledger 只读取执行过的动作；不读取 DOM、数据库、oracle 或版本标签，不代替模型生成动作。

成本：每次推理增加一段动作状态文本；若模型需要全选、纠错、刷新，这些动作照常计入预算，模型调用照常统计。先在 emlog 开发任务上跑配对轨迹。只冻结这一版 ledger，不根据留出结果调提示词。留出尚未运行，不预设改进有效。

开发实现记录：初版 ledger 在 `20261106T164236Z-7e36fc7e`、`20261106T164236Z-37151e5b` 两次 target 试点中重复点击输入框，仍耗尽动作预算。该版没有记录最后动作，提示一直停在“先点击”。随后补记最后执行动作，区分“点击已完成 → 全选”“已全选 → 输入”“输入已完成 → 保存/检查”“刷新已完成 → 判定”。此修正在留出运行前完成；完整对照使用修正后固定实现，原失败试点保留。
